Flow (step by step)

  1. Trigger: Client calls the studio number, day or night.
  2. Input: Vaani Labs answers instantly and streams the transcript plus caller metadata.
  3. Context: System loads services.md, qualified.md, pricing.md (guarded) and past enquiries (as examples, not training).
  4. Processing: Conversation follows the qualified.md checklist; lead fields extracted; lead routed.
  5. AI: Gemini answers live, scores the lead and writes the designer handoff note.
  6. Output: Cal.com books the designer's slot for qualified leads.
  7. Output: Client receives answers and booking confirmation.
  8. Output: Designer receives the handoff email with full context, so no repeated questions.
  9. Output: Every call, outcome and API cost is logged to Nikhil's dashboard.

The Cut

Nikhil wants the system to quote standard per-square-foot pricing. pricing.md says "indicative only, varies by site", so the agent shares only a broad indicative range with a caveat. Firm quotes stay with the designer after a site visit.

Why email (not Telegram) for designer handoff

  • The call is already booked, so a complete written brief matters more than an instant ping.
  • The note sits next to the Cal.com invite, is searchable, and forms a record for the studio.
  • No dependency on 14 designers using a personal messaging app.

Stack

  • Voice and telephony: Vaani Labs
  • LLM: Gemini API
  • Booking: Cal.com
  • Handoff: Email
  • Later: WhatsApp and web form reuse the same Context, Processing, AI and Output; only the Trigger and Input change.
